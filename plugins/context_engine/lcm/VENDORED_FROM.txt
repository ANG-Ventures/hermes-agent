## 2026-08-06 RE-VENDOR: v0.16.2 -> v0.21.0-rc2

NOTE ON THE PRIOR RECORD: the previous VENDORED_FROM.txt claimed v0.16.2 / 03b74f8 while
pyproject.toml claimed 0.19.0. BOTH were wrong for the tree that was actually deployed. Measured
ground truth at re-vendor time: the deployed tree was upstream **v0.16.2 base + ~2705 difflines of
fork modifications + 1 fork-added module (storage_security.py)**. This file now records the real
state; do not trust a bare version string again without diffing against the upstream tag.

Motivating bug (why this re-vendor happened): BELOW-THRESHOLD FORCED COMPACTION. The 0.19-era gate
was naive — `if replay_messages is not None and replay_messages != messages: return True` — so any
turn where LCM externalized a large payload (e.g. an image/media message crossing the 12,000-char
large_output_externalization_threshold_chars) made replay != messages and forced a FULL compaction
regardless of token count. Observed live: a compaction at ~345,087 tokens against a 750,000
threshold. Upstream v0.21 fixes this with the discriminating gate
`_replay_diff_requests_ingest_cleanup` (compaction.py). VERIFIED POST-DEPLOY: engine.py's class body
defines NEITHER should_compress_preflight NOR should_compress, so the CompactionMixin gate is
authoritative and un-overridden.

Upstream architecture change absorbed: LCMEngine was split into mixins —
  LCMEngine(CompactionMixin, ResetStateMixin, ReconcileMixin, AuxiliarySessionMixin,
            PlaceholderLedgerMixin, BypassMixin, ContextEngine)
  new modules: compaction.py, reset_state.py, reconcile.py, aux_session.py,
               placeholder_ledger.py, bypass.py, maintenance.py, message_analysis.py (+ many more)
Module count: 23 -> 62.

FORK SURFACE PRESERVED (do not "clean up" — each is deliberate):
  - fail-open resilience (LCMFailOpenRecoveryError, _handle_fail_open_compression_exception):
    compress DEGRADES (returns messages) instead of raising when raw tokens are below the context
    limit. engine.py's compress() override now delegates to CompactionMixin via super() INSIDE that
    fail-open wrapper.
  - storage_security.py (fork-only module): RowCipher at-rest encryption + the `search_content`
    plaintext FTS index column. The FTS5 external-content table indexes `search_content`, NOT
    `content`, because `content` is ciphertext when encryption_enabled.
  - #465 _merge_adjacent_assistant_messages (never upstreamed) — alternation-clean active context.
  - fresh-tail token budgeting; P2 skew calibration; fork-only `retention_policy` doctor check.
  - `_lcm_summary` marker key: DO NOT REMOVE. It looks write-only inside this plugin but the HOST
    reads it at agent/compaction_stats.py (_LCM_SUMMARY_TAG) with a COMPACTION_STATS_TAG_MISSING
    tripwire.

FORK CODE DROPPED AS SUPERSEDED BY UPSTREAM (verified, not guessed):
  - _compacted_replay_stored_tail_overlap: ReconcileMixin's _find_reconciled_cursor_for_store_tail
    implements the same scaffold-evidence + stored-tail logic AND absorbed the fork's Greptile #107
    refinements. Running BOTH double-counted and DROPPED genuinely-new messages.
  - _coerce_ts: upstream's observed_at / observed_at_source / ingested_at columns separate host
    arrival time from ingest time properly; the fork had overloaded `timestamp` itself.
  - preserved-objective re-anchoring: upstream returns None on reaching a preserved-objective
    scaffold (never promote derived context as current intent) — strictly more conservative, and it
    closes a re-injection hole where a carried block's untrusted <active_memory> body was replayed.
